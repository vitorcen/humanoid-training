人形机器人 Motion 数据集调研：功夫 / 舞蹈 / 多 Prompt 实验

Humanoid Motion Dataset Survey — Kungfu / Dance / Multi-Prompt Experiments   ·   2026-05-22
TL;DR　目标 = 训一个 humanoid 模型，下不同 prompt 做不同动作（功夫、舞蹈、走跑跳）。
KungfuBot 自带数据集只有 7 段 / 62 秒，必须找公开数据集补量。本调研横评 7 个候选，给出三条复刻路径：
🥇Path A：LAFAN1（Unitree 已 G1 retarget）+ KungfuBot 原生 RL pipeline，1–4 天能验。
🥈Path B：HumanML3D（14k motion + 自然语言 caption）→ SMPL retarget → RL，1 周。
🥉Path C：HumanML3D + IsaacSim 多机位渲染 → GR00T N1.7 VLA，2–3 周真做语言 VLA。
Start with Path A. Don't jump to VLA until prompt-conditioned RL works.

4. 三条复刻路径

图 2 · 三条复刻路径流程对比。绿色 Path A 最便宜验证；蓝色 Path C 最贴近真 VLA 范式。

🥇Path A · LAFAN1 + KungfuBot 原生 RL 最推荐起步

为什么先打这个：

  • 零 retarget——Unitree 已经把 LAFAN1 retarget 到 G1 23-DOF，HF 仓 unitreerobotics/LAFAN1_Retargeting_Dataset
  • KungfuBot 原生支持——README 自己点名了，motion_source/convert_lafan_pkl.py 直接吃 csv
  • 数据量提升 70×——496 段 vs 7 段，每段平均长度也更大
  • 覆盖多 prompt 类别：走/跑/跳/格斗/舞蹈/瞄准/坐 (片段名: dance1_subject1、fight_sword1、aiming1_subject1）

命令片段：

# 1. 下载 (LFS)
huggingface-cli download unitreerobotics/LAFAN1_Retargeting_Dataset \
  --repo-type dataset --local-dir datasets/lafan1_g1

# 2. csv → pkl
cd KungfuBot
python motion_source/convert_lafan_pkl.py \
  --filepath datasets/lafan1_g1/dance1_subject1 --start 0 --end -1

# 3. 计算 contact mask
python motion_source/count_pkl_contact_mask.py \
  robot=unitree_g1_29dof_anneal_23dof \
  +input_folder=datasets/lafan1_g1/pkl \
  +target_folder=datasets/lafan1_g1/pkl_with_contact

# 4. 训 PPO (per-motion 或多 motion 共享)
cd humanoidverse
python train_agent.py +exp=motion_tracking_g1 \
  motion_file=path/to/lafan_aggregated.pkl

预期产出：3-5 个 PPO ckpt（每个 prompt 类一个），MuJoCo sim2sim 验证能跑通；上层套个简单分类器把自然语言映射到 ckpt id。

🥈Path B · HumanML3D + text-conditioned RL

为什么打这个：HumanML3D 是目前唯一规模够大 + 带自然语言 caption + SMPL 格式的人体动作数据集（14k motion × 3 caption），caption 就是 "a person performs a karate punch" 这种自然句。

关键工程量：

  • 跑 KungfuBot 的 PHC retarget（SMPL→G1 23-DOF）—— 14k 段 GPU 跑一晚
  • 需要把 RL policy 改成接 text condition：在 actor 输入加 CLIP/T5 embedding（256 维）
  • 因为同一动作有多句 caption，可做对比学习增强 prompt 鲁棒

子集策略：不必跑全 14k——先 grep kungfu|karate|dance|punch|kick 关键词筛 ~500 段做 PoC。

🥉Path C · HumanML3D + IsaacSim 渲染 → GR00T N1.7 VLA

为什么打这个：真要做 VLA（语言+视觉→动作），必须凑齐 (video, state, action, text) 四元组。HumanML3D 给了 (motion, text)，缺 video——只能自渲染。

关键工程量：

  1. retarget SMPL→G1（同 Path B）
  2. IsaacSim 重放每段 motion，3 个机位渲染：3rd-person side / 3rd-person front / ego head-cam
  3. 打包成 LeRobot v3.0 格式：video.mp4 + state.parquet + action.parquet + meta/tasks.json
  4. GR00T N1.7 finetune（参考 LeIsaac PickOrange 现成 pipeline）

风险：

  • G1 不在 N1.7 native embodiment registry，要注册新 EmbodimentTag + projector
  • 渲染 14k 段 × 3 cam × ~10s = 数百 GB
  • VLA 训练需要 ≥A100，4090 24GB 只能 LoRA

建议：先做 A→B 验证 prompt-conditioned RL 真能 work，再投入 C 的工程量。如果 A/B 都不出效果，C 上去也不会有奇迹。

5. 建议执行顺序

阶段数据集训练框架验证目标工作量判停条件
1️⃣ LAFAN1 (G1) 5-10 段 KungfuBot PPO per-motion "原生 pipeline 接上更大数据没崩" 1 天 ≥3 段能稳定 tracking 通过
2️⃣ LAFAN1 (G1) ~30 段 PPO + one-hot motion id "一个 policy 能切换多动作" 2-3 天 切换准确率 ≥80%
3️⃣ HumanML3D 武术子集 ~500 段 retarget + PPO + CLIP embed "自然语言 prompt 选动作" 1 周 未见过的 prompt 表述能找到正确动作类
4️⃣ HumanML3D + IsaacSim 渲染 GR00T N1.7 finetune "真 VLA 跨 prompt 泛化" 2-3 周 新 prompt + 视觉扰动仍能完成
判停哲学：Linus 第一铁律——别破坏不存在的需求。如果 Stage 1+2 在 G1 上 prompt 切换都不稳，Stage 4 上 VLA 就是给问题加复杂度而不是解决它。每一阶段必须先验通过再投下一阶段。
Don't add VLA complexity before prompt-conditioned RL works. Validate at every stage.

6. 已知坑 / Known Pitfalls

  • SMPL 模型文件需要单独申请：HumanML3D / Motion-X / AMASS 都要从 smpl.is.tue.mpg.de 注册下载 SMPL_NEUTRAL.pkl。学术注册即可，但要等几天
  • LAFAN1 Ubisoft 协议是非商用——实验复刻 OK，商用部署不行
  • KungfuBot PHC retarget 用 23-DOF 子集：unitree_g1_29dof_anneal_23dof，腰部/手腕被锁定。如果要做手部动作，需切到 29-DOF 配置
  • IsaacGym → IsaacSim 迁移：KungfuBot RL 在 IsaacGym 训，但 VLA eval 在 IsaacSim。两套 sim 行为有差，建议训完先 sim2sim 验证
  • GR00T 改 embodiment 不只是改 projector：还要改 normalization stats、state/action dim、language tokenizer 输入格式。N1.7 已经支持的 embodiment 列表见 Isaac-GR00T/gr00t/data/embodiment_tags.py
