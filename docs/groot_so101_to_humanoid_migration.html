3. 关键挑战 #1：Demo 数据怎么收？

The single biggest blocker
SO-101 时代你靠的是 LeIsaac SO-101 leader-arm teleop（人手摇杆带动从动臂 → 录下 trajectory）。 HumanoidBench 没有这个。MuJoCo + dexterous hand + 全身协调，无法用单一遥操方案。需要混合策略。

四个候选数据源（按工程量排序）

① Scripted reach skill 推荐起步

HumanoidBench 16 个 task 已内置 reach low-level skill（htarget_low/high）。可写脚本控制器：reach 到物体 → 简单抓取 preset → 移动到目标位姿。

  • ✅ 完全 deterministic，可大量生成
  • ✅ 不需要新硬件
  • ⚠️ 5 个 manipulation gap task（cube/kitchen/cabinet/window/spoon/insert/highbar）没有 reach skill 定义，需先补 htarget bbox
  • ⚠️ 数据多样性差 — 同一脚本生成的轨迹 finetune 后泛化弱

② 自训 DR.Q rollout + 筛选 可考虑

用户 H1-walk 90% / G1-walk 70% ckpt 已 ready，但只 locomotion。

  • ❌ 无 manipulation 通关 ckpt 可作 demo 来源（这是整个项目要解的问题）
  • ✅ 适用于"先 manipulation finetune 出 demo → 再 self-improve"的循环（M2-M3 阶段）

③ 自建 mocap retarget 中等

用现成 human mocap（AMASS / SMPL-H）→ retarget 到 H1 + DEX3-1 → 录 video + action chunk。

  • ✅ 数据自然多样
  • ⚠️ Retarget 难度大，DEX3-1 五指难映射
  • ⚠️ mocap 缺接触信号，HB success_bar 难达成
  • 📚 参考 docs/humanoid_motion_datasets_survey.html

④ Teleop with VR / 手柄 最重

把 LeIsaac teleop 思路移植到 HB MuJoCo：VR 控制器 → IK → H1 双臂 + 抓取 trigger。

  • ✅ 数据质量最高
  • ❌ 需要 VR 设备 + 写 MuJoCo VR bridge（无现成工具）
  • ❌ 工程量超过整个 finetune 本身
推荐组合 / Recommended mix：①（scripted reach）+ ③（mocap retarget 局部使用）。
具体：先给 5 个 gap task 补 htarget_low/high bbox（已在 manipulation brainstorm Path B 列出），用 reach skill 生成 30-50 episode 脚本演示，做 NEW_EMBODIMENT finetune。第一轮成功后用 finetune 出的 policy rollout 收更多样化数据，做 self-improving loop。

4. 关键挑战 #2：modality_configs schema 重设计

SO-101 schema（已通过）

modality_configs:
  new_embodiment:
    video:
      modality_keys: [front, wrist]              # 2 个视角
    state:
      modality_keys: [single_arm, gripper]       # 2 个 state stream
    action:
      delta_indices: [0..39]                     # 40 步 chunk
      modality_keys: [single_arm, gripper]       # ← 同 state

HumanoidBench schema 建议

modality_configs:
  new_embodiment:
    video:
      delta_indices: [0]                         # 单帧（HB 没有训练分布的多帧历史）
      modality_keys: [task_view]                 # 用 task 默认相机
      # 可选: 加 wrist_left, wrist_right 伪视角（需 HB env 改造）
    state:
      delta_indices: [0]
      modality_keys:
        - left_arm                               # 7D arm joints
        - right_arm
        - left_hand                              # ~21D DEX3-1
        - right_hand
        - legs                                   # 11D legs+pelvis (locked during manipulation)
        - waist                                  # H1 没真 waist，可省
    action:
      delta_indices: [0..39]                     # 40 步 chunk，h=40
      modality_keys:
        - left_arm
        - right_arm
        - left_hand
        - right_hand
        # legs 不放入 action — 由 reach skill / lock 控制
        # 或：放入 action 但 loss_weight=0.01，让模型学着"保持站立"
设计取舍：legs 放不放进 GR00T action 是关键决策。
  • 不放（推荐起步）：HB 侧用 reach skill 或固定 standing 姿态控制 legs；GR00T 只学 arms+hands；好处是 GR00T 输出维度小、收敛快
  • 放：GR00T 学全身 23D（不含手）或 61D（含手）；好处是真 end-to-end；坏处是数据需求大 10×，可能不收敛

5. 关键挑战 #3：HumanoidBench observation adapter

SO-101 时代你的 client 是 LeIsaac 的 ZMQ client，喂的是 SO-101 obs（front + wrist + joint）。HB 需要新写一个 wrapper：

# scripts/groot_hb_client.py（新写）
import zmq, numpy as np, gymnasium as gym, humanoid_bench

# 1. 启动 PolicyServer（不变）
#    python run_gr00t_server.py --model-path runs/gr00t_hb_cabinet/ \
#                                --embodiment-tag NEW_EMBODIMENT --port 5555

env = gym.make("h1hand-cabinet-v0", render_mode="rgb_array")
obs, _ = env.reset()
sock = zmq.Context().socket(zmq.REQ); sock.connect("tcp://127.0.0.1:5555")

while not done:
    # 2. HB obs → GR00T nested dict
    obs_dict = {
        "video.task_view": env.render()[None],                     # (1, H, W, 3) uint8
        "state.left_arm":  hb_obs_to_left_arm(obs)[None],          # (1, 7) float32
        "state.right_arm": hb_obs_to_right_arm(obs)[None],
        "state.left_hand": hb_obs_to_left_hand(obs)[None],         # (1, 21)
        "state.right_hand": hb_obs_to_right_hand(obs)[None],
        "annotation.human.task_description": ["open the cabinet drawer"],
    }
    sock.send_pyobj({"obs": obs_dict})
    resp = sock.recv_pyobj()              # action chunk (1, 40, action_dim)

    # 3. GR00T action chunk → HB 61D action
    for t in range(40):
        a_groot = resp["action"][0, t]    # (action_dim,) — 仅 arms+hands
        a_hb = compose_hb_action(
            arms_hands=a_groot,           # 主控
            legs=standing_preset,         # legs 锁定
        )
        obs, r, term, trunc, _ = env.step(a_hb)
        if term or trunc: break

对应的 hb_obs_to_* + compose_hb_action 需要查 dependencies/humanoid-bench/humanoid_bench/h1.py 的 joint 顺序。

9. 风险与失败模式 / Risk register

风险概率影响缓解
Scripted reach 收的 demo 多样性不够 → finetune 过拟合脚本轨迹高中M3 self-improve loop + 随机化物体初态 + state_dropout_prob=0.2（已开）
HB 单视角 + MuJoCo 渲染 OOD 严重，即使 finetune 也不收敛中高退路：手工加 wrist 伪相机（改 HB env mjcf）；或转 Isaac Lab GR-1 任务
DEX3-1 21D 手指 finetune 不足（数据稀疏）中中初版用 power grasp preset（hand action 离散到 open/close）；后期数据多了再放开
action 61D 直接学不收敛（vs SO-101 6D）中高退路：legs 锁 standing + 只学 arms+hands 35D；或转回 IK adapter 路线（zero-shot review §1 方案）
HumanoidBench env reward 与 GR00T 学到的 "看起来对" 不一致低中用 mean_return + 人眼录像双指标，不只看 success_rate
多 task 训练干扰 / 灾难性遗忘中中SO-101 实验显示 N1.7 mix sister PickOrange 反而提升（68.3% > 66.7%）— 可以多 task mix 训
