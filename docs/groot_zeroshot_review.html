0. TL;DR — 一句话

Bottom line
❌ 原计划不值得按现状执行。
最大错误：把 GR00T 当 "吐 7D arm action 的黑盒"。N1.7 实际是 ~38–40D 多模态 chunked action（双臂 EEF + 双手 + 双臂 joint + waist + base/navigate），由 embodiment_tag 绑定，没有 H1Hand 对应 tag。
  • 🅰🅱🅲 三方一致 "54D reach skill 兜底"方案不成立 — 没有 GR00T 与 reach skill 协调的接口；G1→H1 EEF 因臂长不同（60cm vs 90cm）也无线性映射
  • 🅱🅲 视觉跨域几乎致命 — GR00T 训练分布是 RoboCasa / 真实 G1 / GR-1 相机；HumanoidBench MuJoCo 渲染 + 单视角 + 无 wrist view = "换了个世界"（DeepSeek 原话）
  • 🅰🅱🅲 Task 优先级原版排错：HB cube 是 双手 in-hand reorientation（精细接触最难），不是 PickOrange tabletop pick；highbar 是 whole-body locomotion，应从 manipulation 计划删除
  • 🅱🅲 Action API 不是 .predict() — GR00T 用 ZMQ PolicyServer/PolicyClient；action chunk horizon 实际 ~16；4 步 flow matching 去噪；15 Hz 控制频率（DROID example）
  • 🅱🅲 更聪明的路径：Day 1-2 跑官方 LIBERO/DROID demo 闭环；Day 3-4 Isaac Lab GR-1/G1 closed-loop（白皮书已验证）；Day 5-7 才进 HB，先 ReplayPolicy smoke test，后期靠 LoRA finetune 而非 zero-shot

1. 三方原文摘要 / Three reviewers in their own words

🅰 Opus 4.7（本机 ground truth）

读到的真相：

  • N1.7 backbone = nvidia/Cosmos-Reason2-2B（Qwen + SigLip2）
  • Flow-matching diffusion action transformer，action_horizon=50，num_inference_timesteps=4
  • 训练 embodiment：xdof_relative_eef_*、oxe_droid_*、real_g1_*、real_r1_pro_sharpa_* — 无 H1
  • REAL_G1 modality keys = left_wrist_eef_9d, right_wrist_eef_9d, left_hand, right_hand, left_arm, right_arm, waist, base_height_command, navigate_command
  • video delta_indices = [-20, 0] ⇒ 21 帧历史
  • max_state_dim/max_action_dim = 128，max_num_embodiments = 32

🅱 GPT-5.5（外部源码 + Policy Guide）

关键判定：

  • "7D 给 arm，54D 给 reach skill 基本是糊纸墙"
  • "DROID zero-shot 期望外部相机 + wrist camera，HB 单 rgb_array 缺 wrist view"
  • "embodiment_id 不是装饰，它索引 embodiment-specific encoder/decoder；H1Hand 没有对应 id，这就是核心风险"
  • "cube 是双手 in-hand reorientation，不是 PickOrange — 把'物体是 cube'当相似性是坏抽象"
  • "highbar 不该放在这条线里 — 是 whole-body dynamic locomotion"
  • "success_rate > 0 太低，随机碰一下也算成功"

🅲 DeepSeek-V4-Pro（白皮书 + model card）

关键判定：

  • "视觉域差距是最致命的。不是'换个角度'，是'换了个世界'"
  • "H1 和 G1 的手是两种生物：G1 平行爪 ~2D vs H1 DEX3-1 ~30D 五指"
  • "GR00T 不是 model.predict() — 用 ZMQ server-client 架构，run_gr00t_server.py + PolicyClient"

4. §3 Embodiment / Prompt — 可配但效果未知

  • 没有 H1 embodiment tag。最接近的入口 = real_g1_relative_eef_relative_joints（双手人形，但 G1 130cm vs H1 180cm，臂长差 30cm）
  • Language key（G1 schema）= annotation.human.task_description
  • Prompt 风格：短句、动作导向、贴训练语料
    • ✅ "pick up the cube" / "open the cabinet door" / "wipe the window"
    • ❌ HB reward 描述 / 多目标长句 / 多步任务分解
  • Policy API 是 nested dict，不是 chat： 
    obs = {
    "video.ego_view":       (1, 21, 224, 224, 3) uint8,
    "state.left_wrist_eef_9d":   (1, 1, 9) float32,

    "annotation.human.task_description": ["pick up the cube"],
}
  • 调用方式：GR00T 用 ZMQ PolicyServer / PolicyClient，不是 model.predict()

7. §6 致命遗漏清单 / Engineering pitfalls

  1. Action chunk horizon：N1.7 训练 horizon=50（config）但推理上限 16（DeepSeek）— 别傻 open-loop 跑 40 步
  2. Diffusion timesteps：num_inference_timesteps=4（flow matching 快速去噪）
  3. 控制频率：DROID example 用 15 Hz；HB 默认 100 Hz；需 action_repeat ≈ 6-7 对齐
  4. Normalization：use_percentiles=true，依赖 statistics.json（G1 数据）。直接喂 H1 物理范围会动作爆炸 — 必须先 normalize 到 G1 量级
  5. EEF 旋转 6D ↔ 旋转矩阵 换算极易反向，需单元测试
  6. HB action space 是 [-1, 1]^61 normalized，不是关节角弧度
  7. 21 帧历史：cold start 时前 20 步要么复制首帧要么 zero-pad — 影响初始动作
  8. Reset 分布固定：物体初态随机化太大，zero-shot 看起来失败可能是初态外的问题
  9. "success_rate > 0" 太低（🅱）— 随机碰一下也算；改为 "mean_return > baseline + sanity 视频"
  10. 没有 chat_template.json（🅲 实测 404）— prompt 直接走 text encoder，不要套 chat 格式

8. §7 一周 Shortcut — 三方共识路径

9. 修订后的执行计划 / Revised plan

核心变更 / Core changes
  1. 放弃 "7 task zero-shot" 目标 — 改为 "证明 pipeline 闭环 + 1-2 task fine-tune nonzero success"
  2. Highbar 移出 manipulation 线 — 是 whole-body locomotion，转交 DR.Q 或独立计划
  3. 第一周不碰 HB — 强制走官方 LIBERO/DROID + Isaac Lab GR-1 闭环
  4. Adapter 设计：REAL_G1 tag → EEF + IK → H1 arms (14D)；hand 用 grasp preset；legs/torso 锁定或 reach skill；waist/base/navigate mask
  5. 架构：PolicyServer (ZMQ) + HB-side PolicyClient wrapper
  6. 验证步骤补充：先用 ReplayPolicy 跑通 HB env loop，再换真实模型
  7. Finetune 预算预留：20-50 episodes scripted/reach-skill demos → LoRA

新版 First-3-steps checklist

  1. Step 1 — 官方 demo 闭环（不碰 HB）
    git clone https://github.com/NVIDIA/Isaac-GR00T，跑 LIBERO 或 DROID example，启 PolicyServer + Client，open-loop MSE 跑通，录视频。
    Acceptance：官方 demo 视频跑出来，pipeline 通。
  2. Step 2 — HB → GR00T observation adapter
    写 scripts/groot_hb_adapter.py：HB obs → REAL_G1 nested dict（state 用 H1 FK 算 EEF + gripper proxy；video 用 HB camera + 21 帧 ring buffer + 224×224 resize）。先用 ReplayPolicy 验环境循环，不调真实模型。
    Acceptance：reset → obs → step → reward 循环不崩，obs dict shape 全对。
  3. Step 3 — 接 GR00T-N1.7 REAL_G1 zero-shot on cabinet
    PolicyClient.get_action() → IK (EEF → H1 arms) → grasp preset → HB action[-1,1]^61。一个 episode 不崩 + 录视频。
    Acceptance：完整 episode 不爆 normalization；视频里 arm 朝 cabinet 方向移动（不要求成功，要求"看起来在尝试"）。
