0. TL;DR

Bottom line first
  • 问题 / Problem：HumanoidBench 27 个任务里 9 个 manipulation 类（cube · kitchen · door · cabinet · basketball · window · spoon · insert×2 · highbar_hard）没有任何可视化的训练策略可下载。官方明确不放，DR.Q 社区 ckpt 只覆盖 locomotion，且这些 task 不支持 reach 低层技能 wrapper。
  • 结论 / Verdict：三方独立确认无 drop-in ckpt。Opus 4 路径 + Codex 4 路径 + DeepSeek 4 路径 = 12 条互补方案。按"出图速度 × 真实任务完成度"排序见 §5。
  • 推荐优先级 / Recommended priority：
    1. 0 工时 · 立即 5 个支持 reach 的 manipulation task（package/truck/bookshelf×2/push）— 已可视化
    2. 1-3 天 · 立即 脚本 IK 控制器（DeepSeek 推荐路径 4 ⭐）— 无 ckpt 无 GPU，door/cabinet/window/basketball/cube/spoon 5-6 task 拍照级可视化
    3. 小时级–1天 · 短期 π0.5 VLA 零样本（DeepSeek 路径 1 ⭐）— 最快看结果，关键是写 action decoder
    4. 1-3 小时 · 短期 给 cube/door/cabinet/window/spoon/basketball 补 htarget_low/high + 复用 reach skill（Opus 路径 B）
    5. ~1 天 · 短期 UMI-on-Air ckpt 适配 cabinet（Codex 路径 #1）
    6. 数天 · 中期 TrajBooster (G1 VLA) / iDP3 / RoboCasa BC，三选一 retarget 实验
    7. 数天 · 中期 自训 Dreamer/TDMPC2 medium 从 window/spoon 开始（易任务先）
    8. 长期 训出 SOTA + 回放给社区，填补 carlosferrazza/humanoid-bench issue #22/#66 的需求
  • 三方共识 / Triangulated consensus：先解 action-space mismatch (action decoder)，这是任何外部 ckpt 接入 HB 的头号杀手（DeepSeek 关键洞察 + Codex 4 个候选全部都需要）。

3. 解法 / Proposals

Ranked by feasibility × time-cost × visual reward

🅰 Claude Opus 4.7 视角 — 4 条路径

路径 A：边缘任务即时可视化 / Edge-task quick wins（0 工时）

下列 manipulation task 其实已支持 reach skill wrapper（已在 §2 之外）：push · package · truck · bookshelf_simple · bookshelf_hard。 These tasks already declare htarget_low/high and run with the upstream reach skill — visible arm motion right now.

python scripts/native_viewer.py --env h1hand-package-v0 \
    --policy_path dependencies/humanoid-bench/data/reach_two_hands/torch_model.pt \
    --mean_path   dependencies/humanoid-bench/data/reach_two_hands/mean.npy \
    --var_path    dependencies/humanoid-bench/data/reach_two_hands/var.npy \
    --policy_type reach_double_relative
路径 B：给缺口 task 补 htarget_low/high 后复用 reach skill（1-3 小时/task）

真正的 9 个缺口里，cube/door/cabinet/window/spoon/basketball 的"目标位置"在物理上其实清晰可定义（门把手位置、橱柜把手、勺柄、篮筐等）。在 task class 加两行 htarget_low/high = np.array([...]) 即可让 reach skill 跑起来。 For cube/door/cabinet/window/spoon/basketball, the "hand target region" is physically well-defined (door handle, cabinet pull, spoon shaft, basketball, …). A 2-line patch enables the reach skill.

风险 / Risk：不能完成任务，只能让手臂"伸向目标"——视觉化升级，policy 不会真的开门或扔球。Yields visual richness, not true task completion.

路径 C：自训 DreamerV3 / TD-MPC2 medium，单任务 0.5–1 天

论文里这些 task 训练曲线在 logs/main_results.json 都有；4090 + medium size（~25M params）单任务 4-12 小时能跑到 ~ 50–80% 报告水平。Paper-reported curves exist for all 27 tasks; medium-size Dreamer on a 4090 reaches 50–80% of the published score in 4–12 h per task.

用 humanoid_benchmark preset，不是默认（默认 deter=6144 太大）：

# 在 dependencies/humanoid-bench/dreamerv3/ 下
python embodied/agents/dreamerv3/main.py \
    --configs humanoid_benchmark medium \
    --task humanoid_h1hand-cube-v0 \
    --logdir ~/logdir/cube-medium-seed0

风险 / Risk：9 个任务 × 0.5-1 天 = 1-2 周；cube/insert_small 论文都没解，自训也大概率失败。9 tasks × 0.5–1 day = 1–2 weeks; cube and insert_small are unsolved even in the paper.

路径 D：等社区 / 自训 Simba 大模型（不可控）

SimbaV2 (joonleesky/simbaV2) 已经在 HF 放了 14 个 humanoid-bench task 的 训练 replay buffer（11.1 GB / 122K ep）—— 这是离线 RL 训练原料，不是 policy。用它训 Decision Transformer / CQL / IQL 是可行的 fallback，但跟自训 RL 一样要算力。SimbaV2's dataset is offline RL fuel, not a policy. Training DT/CQL/IQL on it is feasible but not free.

DeepSeek 的关键洞察 / DeepSeek's key insight

"Action space 不匹配是 sim2sim 失败的头号杀手"。RoboCasa/π0.5/UMI-on-Air 都输出 task-space (EE pose / Cartesian)，而 HumanoidBench 是 joint torque/position 控制。任何外部 policy 接入前要先解决这个 action decoder。 "Action-space mismatch is the #1 killer of sim2sim transfer." Every external policy (RoboCasa, π0.5, UMI-on-Air) outputs task-space (EE pose), while HumanoidBench expects joint torque/position. Solve the action decoder first.

4. 评测框架 — Success / Subtask / Timeout / Time

Eval framework — wire the bench's own signals into the viewer

HumanoidBench 的 task class 已经提供完整的 success / subtask 信号，不需要外部 ground truth。只要 viewer 在循环里读 info 和累加 reward，就能算出所有指标。 HumanoidBench tasks already emit per-step success / subtask info — the viewer just needs to read them.

建议的 episode 指标 / Recommended episode metrics

@dataclass
class EpisodeStats:
    task: str
    seed: int
    ep_steps: int                  # 步数 / steps used
    ep_return: float               # 累计 reward / cumulative reward
    success: bool                  # info['success'] 任意 step True 或 ep_return ≥ success_bar
    subtasks_max: int              # max(info['success_subtasks']) — kitchen / cabinet 才有
    time_to_success_s: float | None  # 第一次 success=True 的 wall time
    timed_out: bool                # truncated == True 且 not success
    wall_time_s: float             # 完整 episode wall time
    fps: float                     # ep_steps / wall_time_s

"成功 / 失败 / 超时" 三态判定 / Tri-state outcome

# 关键判定逻辑 / Key logic
SUCCESS_BAR = base.task.success_bar   # task class 提供

def step():
    obs, reward, terminated, truncated, info = env.step(action)
    ep_return += reward
    # success 优先：env 自己说 True，立即记
    if info.get('success', False):
        success = True; time_to_success = wall_now()
    # cumulative reward 达标也算（locomotion 这类没 info['success']）
    elif ep_return >= SUCCESS_BAR:
        success = True; time_to_success = wall_now()
    # episode 结束时
    if terminated or truncated:
        timed_out = truncated and not success
        # 落账 EpisodeStats，重置
