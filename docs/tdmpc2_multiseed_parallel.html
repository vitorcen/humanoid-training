TD-MPC2 多 seed 并行训练实战
TD-MPC2 Multi-seed Parallel Training — Field Notes

Date: 2026-05-27 · Hardware: AutoDL RTX 4080 SUPER (32 GB) · Source experiment: humanoid_g1-walk-v0, model_size=5

TL;DR: TD-MPC2 上游没有原生并行实现（单进程单环境），但通过启动多个独立 seed 进程 在同一 GPU 上自然时间分片，3 个 seed 并行使整卡吞吐 11 → 30 sps（2.7×）， 每个 seed 个体步速仅下降 ~10%。代价：32 GB 显存吃满 6 GB，CPU 12 核被均分。

TD-MPC2 has no native parallelism (1 process, 1 env). But spawning multiple independent seed=N processes on the same GPU naturally time-slices the GPU: 3 seeds yield 2.7× wall-clock throughput, with each seed only ~10% slower individually.

1. 背景：为什么单 seed 不够 / Why one seed is not enough

RL 训练对随机种子极敏感——同算法、同超参、同任务，不同 seed 收敛曲线可相差 30-50%。 Paper 报"H1-walk TD-MPC2 mean 750"是 3-5 seed 平均，单 seed 几乎没统计意义。

RL is notoriously seed-sensitive. Same algorithm, same hyperparameters, same task, different seeds can give 30-50% return spread. Paper-reported numbers are 3-5 seed averages; single seeds are not statistically meaningful.

实测我们自己 H1-walk DR.Q 多 seed 数据：
seed 0 → mean ≈ 530 · seed 10 → mean ≈ 295 · seed 20 → mean ≈ 382
Range: ±40% with same config.

3. 原理：为什么 GPU 利用率从 15% 跳到 98% / Why GPU util jumps 15% → 98%

核心机制：TD-MPC2 单进程的时序是 CPU step → GPU plan → CPU step → GPU plan … 交替进行，GPU 在 CPU step 阶段完全 idle（15% util 平均）。
3 进程并行后，每个进程独立按此节奏跑，但不同进程的 CPU step / GPU plan 阶段错峰， GPU 在任意时刻几乎总有进程在请求它（98% util）。

Core mechanism: A single TD-MPC2 process alternates CPU step → GPU plan; GPU sits idle during CPU stepping (avg 15% util). With 3 concurrent processes, their CPU/GPU phases interleave; the GPU almost always has at least one process requesting it (98% util).

1M 步完成估算：

  • 单 seed @ 11 sps：~25 h，得 1 个数据点
  • 3 seed 并行 @ 10 sps each：~28 h，得 3 个统计独立数据点
  • 3 seed 串行（每个跑完再下一个）：~75 h，得 3 个数据点
结论 / Verdict：相比串行多 seed，并行节省 2× wall time。 相比单 seed，仅多 12% wall 即可拿 3× 的统计可信度。
2× wall-time savings vs serial multi-seed; only 12% extra wall for 3× statistical confidence vs single seed.

5. 启动配方 / Launch recipe

每个 seed 一个 tmux session（独立 logdir 由 TD-MPC2 cfg 自动分到 logs/<task>/<seed>/<exp_name>）：

# SSH 进 AutoDL
ssh -p 12770 root@connect.bjb1.seetacloud.com

# 每个 seed 一个 tmux session
for SEED in 0 10 20; do
  tmux new-session -d -s "g1train_s${SEED}" -x 220 -y 50
  tmux send-keys -t "g1train_s${SEED}" "
    cd /root/autodl-tmp/humanoid-training/runs/g1_tdmpc2_pilot && \
    MUJOCO_GL=egl /root/miniconda3/bin/conda run -n humanoidbench --no-capture-output \
      python -m tdmpc2.train \
      task=humanoid_g1-walk-v0 model_size=5 steps=1000000 eval_freq=50000 \
      seed=${SEED} exp_name=g1_tdmpc2_pilot \
      data_dir=/tmp/_g1_tdmpc2_buf_s${SEED} \
      checkpoint=null disable_wandb=true save_agent=true save_csv=true \
      2>&1 | tee train_s${SEED}.log
  " Enter
done

关键点 / Key:

  • data_dir 每个 seed 必须不同，否则共享 replay buffer 文件破坏统计独立性 / each seed needs its own buffer dir
  • MUJOCO_GL=egl 必须，否则容器无 display → mujoco gladLoadGL 报错
  • checkpoint=null 让所有新 seed fresh-from-scratch；要 fine-tune 则填具体 .pt
  • tmux session 与 SSH 完全解耦——断网不会停训练 / SSH disconnect-safe

6. 缺点 / 注意事项 / Caveats

  • CPU 竞争阈值：12 核分给 3 个 seed 各 ~4 核，TD-MPC2 单进程 MuJoCo 物理仿真不是 thread-heavy（基本单核），所以 4 核够；但跑 6+ seeds 会开始 thrash。
    12 cores / 3 seeds = 4 each. MuJoCo physics is mostly single-threaded; beyond 6 seeds you'll thrash.
  • GPU 内存非问题：每个 TD-MPC2 model_size=5 进程仅 ~2 GB GPU 显存，32 GB 卡可塞 ~12 seed。
    ~2 GB per seed; 32 GB card can hold ~12.
  • seed=0 heterogeneity：我们的 seed=0 是 resume from step_250k.pt，而 seed=10/20 fresh， 跨 seed 平均时这是 apple-vs-orange。要严格 paper-comparable 需 3 个 seed 都 fresh init。
    Our seed=0 is fine-tuned from a 250k-step checkpoint; seed=10/20 are fresh. Strictly comparable multi-seed averaging requires all-fresh init.
  • 磁盘 IO：3 个 replay buffer 写盘竞争 NVMe；AutoDL /tmp 通常本地 NVMe 没问题， 但是 autodl-tmp 网络盘要小心写 buffer。
    Replay buffer disk contention — use local /tmp, not network-mounted dirs.
  • 异常恢复：单 seed 进程崩了，另两个继续跑；可独立重启。
    Each seed is fully independent; a crash on one doesn't affect the others.

7. Linus 反思 / Linus retro

  1. 真问题？ ✅ TD-MPC2 paper-level 报告需要 multi-seed，否则 single-seed 没说服力。
  2. 更简单方案？ 单 seed 跑久点+多次 reruns 用 wallclock 换 evidence——但 3× wall 太贵。 并行才是数据结构对路的方案。
  3. 会破坏什么？ 不会。每个 seed 是 hermetic 进程，无共享状态，无竞争条件。

设计品味：原 TD-MPC2 trainer 没考虑多 seed 编排——但我们不需要改它， 操作系统 (tmux + 进程隔离) 已经提供了完美的并行原语。消除特殊情况 = 不写新的多 worker 代码。
Original TD-MPC2 trainer doesn't think about multi-seed orchestration — but we don't need to patch it. The OS (tmux + process isolation) already gives us the parallel primitive. Eliminating special cases = not writing new multi-worker code.
